# Issue 16：正式防重入 DLL 的補充回歸

本輪依使用者要求補測試；不修改已發布安裝器、不變更版號或擴大資料工作。#18、#19 已依使用者決定補上 PR 並關閉。

## 測試範圍

沿用既有 WiX SDK、MinGW 及 PowerShell runner 慣例。現有七項原生案例測的是 guard header，這次直接載入正式建置的 `LiuKaiInstallerGuard.dll`，執行 BAFunctionsCreate／Destroy 的元件測試：

1. 不完整參數或錯誤 API 版本拒絕，失敗不得發布 callback。
2. BA fixture 正常結束或中斷後，只要 keeper 仍在，第二個客戶端仍被拒絕；keeper 結束後才可重新取得保護。
3. 有鎖時，合法 embedded upgrade 的內部移除（UNINSTALL）及失敗還原入口（INSTALL）仍能執行。quiet、錯誤 relation/action 不得略過保護。

使用自建 fixture 子程序、事件握手及 kill-on-close job；不安裝 MSI、不啟動真正 Burn、不終止現有安裝引擎、服務或應用程式。於單一 Windows 沙盒驗證，保留 Windows 可用記憶體至少 30 GiB，D 槽至少 82 GiB；不啟動或查詢 WSL。

## 證據界線

這是實際 DLL 與程序生命週期的元件驗證，不等同真實 MSI 已提交、BA 中斷後普通雙擊恢復的端到端驗證；也不等同完整 Burn rollback 已驗收。歷史 `0x800700e8` 根因不因此宣告已修。#16 仍保持開啟，直到其原本恢復驗收有直接證據。
